## 1. 回答：先存 ArtifactRawTable 还是直接插入 RAG？

**推荐先存 ArtifactRawTable 再 `alingest_artifacts()` 到 RAG。** 理由：
- `alingest_artifacts()` 已存在 (`document.py:280-329`)，从 ArtifactRawTable 读取 → 构建 Document → `aadd_documents` 完整流程
- 与 Spider pipeline (`spider/pipeline.py`) 保持一致，ArtifactRawTable 是文物的规范存储
- 数据可重复 RAG 摄入，不依赖 CSV 文件
- 支持按博物馆、按数量增量摄入

## 2. 新建 `knowgraph/adapters/` 模块

```
knowgraph/adapters/
├── __init__.py         # 导出 BaseAdapter, get_adapter
├── base.py             # BaseAdapter 抽象基类 + pandas NaN 安全工具函数
└── philamuseum.py      # PhilaMuseumAdapter: clean_artifacts.csv 适配器
```

### `base.py` — 抽象基类
```python
class BaseAdapter(ABC):
    @abstractmethod
    def row_to_dict(self, row: dict) -> dict:
        """将单行 pandas dict 转为 ArtifactStore.ainsert_artifacts 可用的扁平 dict"""
    
    def load_references(self) -> None:
        """加载辅助查找表 (dynasties, museums 等)"""
    
    def validate_row(self, row: dict) -> bool:
        """校验行数据有效性"""
```

还包含共享的 pd.isna 安全工具函数 (`_safe_str`, `_safe_int`)。

### `philamuseum.py` — 当前测试数据的适配器
处理 `clean_artifacts.csv` 的列映射：
- `title_zh` / `title_en` → `title`
- `time_period` | `dynasty_id`(查 `clean_dynasties.csv`) → `period`
- `museum_id`(查 `clean_museums.csv`) → `museum`
- 列名直接映射: `type`, `material`, `description`, `dimensions`, `detail_url`, `image_url`, `credit_line`, `accession_number`, `crawl_date`

## 3. 修改 `tests/test_real_rag.py`

